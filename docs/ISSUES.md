记录本项目实际遇到的问题、诊断证据、原因归属、处理方式与验证结果。记录中的本地处理状态与 GitHub 源码、Release 的发布状态分开说明。

## ISSUE-20260914-01：应用更新后主题背景被白底遮挡

### 基本信息

- 发现及修复日期：2026-09-14。
- 环境：Windows 11，MSIX 版 ChatGPT / Codex Desktop `26.908.4834.0`。
- 本地状态：已修复并热更新，当前窗口背景恢复，本次处理未重启应用。
- 影响范围：四套内置主题的公共背景适配逻辑，以及使用同一 CSS 模板的自定义背景。
- 本次同步范围：问题记录及 README 入口；本地已修复不代表 GitHub 源码或 Release 已发布该修复。

### 故障表现

应用更新后，背景图片看起来全部消失，主内容区呈白色；主题配色、边框、主题切换菜单和首页漫画卡片仍然存在。对话页的部分装饰也未正确挂载。

涉及的内置主题：

- `madoka-after-school-2k`（见泷原放课后）。
- `madoka-notebook`（叛逆的物语）。
- `madohomu`（圆焰）。
- `moonlight-crystal-2k`（名侦探光之美少女）。

### 诊断证据

| 检查项 | 修复前实际结果 | 说明 |
| --- | --- | --- |
| 自动加载与注入 | 守护进程、监视器及本机 CDP 端口正常，主题样式已存在 | 自动加载链路仍在工作 |
| 背景图片 | `#root` 的计算样式包含背景图片，当前主题图片可解码为 3840×2160 | 图片数据未丢失 |
| 主内容区结构 | 类名已变成 `_MainContentSurface_…`，仍保留 `data-app-shell-main-surface="default"` | 旧类名选择器不再命中 |
| 主内容区背景 | 计算背景色为 `rgb(255, 255, 255)`，来自原生 `var(--color-surface)` | 白色底层遮住了后方背景 |
| 对话页装饰定位 | 旧代码查找 `main.main-surface` | 新版主内容区无法被装饰器识别 |

这些证据将本次问题定位到 DOM/CSS 适配层，而不是账号、图片文件或引擎版本选择。

### 原因与责任归属

本次属于**官方界面更新触发的第三方主题兼容性故障**。

官方更新改变了主内容区的内部 DOM/CSS 类名；主题项目仍依赖旧的 `.main-surface`、`main.main-surface`，导致背景透明规则和装饰定位规则失配。原生白色背景因此显示在主题图片上方。

现有证据不足以将其认定为官方应用自身的 Bug。官方更新是触发条件，主要维护改进点在本项目对内部页面结构的依赖与兼容处理。应保留新旧结构识别，而不能假定内部类名长期不变。

### 本地修复

本次本地修改涉及：

- `src/skin-css.mjs`：公共主内容区背景规则支持 `[data-app-shell-main-surface]`。
- `src/madoka-css.mjs`：首页、对话页的背景及装饰定位规则兼容新版主内容区。
- `src/magical-presets-css.mjs`：其余主题的背景、场景和边框规则同步兼容。
- `src/skin-menu.mjs`：对话页装饰根节点同时识别 `main[data-app-shell-main-surface]` 和 `main.main-surface`。

保留旧类名选择器；不硬编码动态类名中的构建哈希，也不将全局 `--color-surface` 改成透明，避免影响菜单、弹窗等原生界面。

修复已同步到本地源码与实际安装运行目录，并在已有 CDP 连接上热更新当前主题。未修改 MSIX、应用二进制、内置 Codex 引擎或引擎覆盖设置。

### 验证结果

1. 浏览器回归包含 5 类主题模板 × 2 类页面（首页、已有对话页）× 2 类结构（旧版、新版），共 20 个场景。
2. 修复前：10 个旧版结构场景通过，10 个新版结构场景全部复现白底遮挡。
3. 修复后：20 个场景全部通过，同时验证装饰根节点、定位、主题菜单唯一性及恢复原生界面。
4. 相关 CSS、菜单、注入器和内置素材测试共 23 项通过。
5. 当前真实窗口的主内容区背景色恢复为 `rgba(0, 0, 0, 0)`，主题渐变生效；背景图片解码正常，场景及边框各保留一个，截图确认背景恢复。
6. 四个修改文件的源码与安装副本哈希一致，测试 iframe 已清理，应用主进程未重启。

本地浏览器回归脚本为 `test/surface-compatibility.browser.test.mjs`。以下命令适用于已包含该脚本及本次修复的工作副本，并要求应用原有调试端口可用：

```powershell
$env:HEIGE_TEST_CDP_PORT = '9341'
node --test test/surface-compatibility.browser.test.mjs
Remove-Item Env:\HEIGE_TEST_CDP_PORT
```

该检查只创建并销毁离屏测试 iframe，不切换当前任务、不修改当前主题、不重启应用。

### 后续维护要点

- 应用更新后若“配色仍在、背景变白”，先检查主内容区计算背景色、主题选择器是否命中，以及背景图片是否可解码。
- 优先使用页面提供的语义属性识别组件，同时保留旧版回退；语义属性也应随应用更新验证。
- 背景透明规则、装饰根节点查找和装饰定位 CSS 必须一起维护。
- 验证应覆盖全部主题、首页、对话页及恢复原生界面，不能仅检查“样式已经注入”。
- 调试连接可用时优先热更新；如果必须重启，先完成修复准备，再交由用户手动重启。
